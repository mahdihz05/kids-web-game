# نسخه ۲: حساب‌ها و گزارش عملکرد

این نسخه برای استفادهٔ خصوصی مجموعه طراحی شده است. ورود عمومی به بازی جای خود را به حساب والد، کد دعوت و انتخاب پروفایل کودک داده است.

## راه‌اندازی برای مدیر

1. مسیر `/admin` را باز کنید و با **رمز مدیریتی موجود** وارد شوید.
2. در «کاربران و عملکرد ← مدارس، دعوت و حساب والد» مدارس را ثبت کنید.
3. یک دعوت با عنوان، تعداد ثبت‌نام مجاز و تاریخ اعتبار بسازید. کد فقط هنگام ساخت نمایش داده می‌شود.
4. کد را به والد تحویل دهید. والد از صفحهٔ اصلی نام خود، نام کاربری و رمز حداقل ۱۰ کاراکتری را ثبت می‌کند.
5. والد برای هر کودک نام، نام خانوادگی، سن، مدرسه و تصویر ثبت می‌کند. شناسهٔ `K-…` به‌صورت خودکار و ثابت ساخته می‌شود.
6. برای بازیابی دسترسی والد، مدیر رمز جدید می‌سازد؛ تمام نشست‌های قبلی آن حساب بسته می‌شوند. والد می‌تواند رمز را در پروفایل خودش تغییر دهد.

مدیر می‌تواند حساب والد را غیرفعال کند. والد فقط به کودکان خودش دسترسی دارد. اطلاعات هویتی کودک از شناسهٔ رویدادها جدا نگهداری می‌شود؛ در گزارش مجاز این دو به هم متصل می‌شوند.

## داده‌های ذخیره‌شده

- هر نوبت بازی شناسهٔ مستقل و پیشرفت قابل ادامه دارد. تکمیل و بازی دوباره دو نوبت مستقل‌اند.
- سن، مدرسه و نسخهٔ امتیازدهی در همان نوبت ذخیره می‌شوند؛ ویرایش پروفایل گزارش گذشته را عوض نمی‌کند.
- ورود به مرحله، پاسخ قطعی و پیش‌انتخاب، تلاش اشتباه، کشف سرنخ، ابزار صحیح/اشتباه، ساخت، بازاندیشی، بازکردن کتاب، درخواست پخش صوت، ادامه، توقف، فعالیت و تکمیل ثبت می‌شوند.
- رویداد صوت، **درخواست کاربر برای پخش/توقف** را ثبت می‌کند؛ موفقیت واقعی موتور گفتار مرورگر تضمین نمی‌شود.
- سرور ترتیب و مالکیت رویداد را بررسی و پیشرفت و امتیاز را با همان موتور بازی بازسازی می‌کند. امتیاز ارسالی مرورگر مرجع گزارش نیست.
- ارسال مجدد یک شناسهٔ رویداد، امتیاز یا نتیجه را تکرار نمی‌کند. رویدادهای ارسال‌نشده در صف اختصاصی همان کودک باقی می‌مانند و در دسته‌های حداکثر ۱۰۰تایی ارسال می‌شوند.
- ادامهٔ نوبت فعال هنگام اختلال شبکه ممکن است؛ شروع نوبت جدید، انتخاب کودک و خروج از حساب نیازمند ارسال صف معوق و اتصال‌اند. بستن مرورگر صف را حذف نمی‌کند.
- زمان فعال از فاصلهٔ رخدادها و فعالیت صفحهٔ قابل مشاهده به دست می‌آید؛ هر فاصله حداکثر ۶۰ ثانیه و حداکثر زمان سپری‌شده است. این مقدار برآورد فعالیت است، نه زمان نگاه‌کردن کودک به صفحه.
- پیشرفت و آمار ناشناس نسخهٔ ۱ حذف نشده‌اند و به هویت کودک نسبت داده نمی‌شوند. آمار قدیمی در گزارش تجمیعی و خروجی Word باقی است.

## قواعد امتیاز، ستاره و مدال (نسخهٔ ۲٫۰)

امتیاز هر پاسخ یا فعالیت از قرارداد همان داستان خوانده می‌شود. برای انتخاب‌های یک مرحله، بیشترین امتیاز کسب‌شده نگهداری می‌شود؛ تکرار پاسخ مشابه امتیاز اضافه نمی‌کند. سرنخ، ابزار و بخش ساخته‌شده فقط یک بار امتیاز می‌گیرند. بازاندیشی در اولین پاسخ امتیاز می‌گیرد؛ تغییر پاسخ بعدی در رویدادها ثبت می‌شود و امتیاز اضافه ندارد.

درصد نتیجهٔ کامل = امتیاز خام تقسیم بر مجموع امتیازهای قابل کسب در مراحل مسیر طی‌شده × ۱۰۰. مراحل شاخهٔ دیگری که کودک از آن عبور نکرده وارد مخرج نمی‌شوند. برای نتیجهٔ ناقص، درصد پیشرفت امتیازی نسبت به کل فرصت‌های داستان نمایش داده می‌شود. درصد مهارت فاقد فرصت سنجش، «—» است.

| درصد نتیجهٔ کامل | ستاره |
| --- | --- |
| کمتر از ۵۰ | ۱ |
| از ۵۰ تا کمتر از ۸۰ | ۲ |
| ۸۰ و بیشتر | ۳ |

| درصد نتیجهٔ کامل | مدال |
| --- | --- |
| کمتر از ۶۵ | برنز |
| از ۶۵ تا کمتر از ۸۵ | نقره |
| ۸۵ و بیشتر | طلا |

تکمیل هر مأموریت نشان اختصاصی همان مأموریت را می‌دهد. مجموع ستاره‌های کودک از **بهترین نتیجهٔ هر بازی** محاسبه می‌شود؛ تکرار بازی مجموع را بی‌دلیل زیاد نمی‌کند. همهٔ مدال‌ها و نتایج هر نوبت در تاریخچه باقی می‌مانند. امتیاز، ظرفیت مسیر، درصد مهارت‌ها و نسخهٔ قواعد هنگام ثبت نتیجه در سرور حفظ می‌شوند.

این آستانه‌ها قواعد اجرایی نسخهٔ حاضرند؛ اعتبارسنجی علمی مهارت کودک محسوب نمی‌شوند. برای مقایسهٔ دقیق، بازی و نسخهٔ قواعد یکسان و مسیرهای انتخابی نیز بررسی شوند.

## گزارش‌ها

والد خلاصهٔ نتایج و نمودار تغییر عملکرد را برای کودک انتخاب‌شده می‌بیند. بازی پیش‌فرض آخرین بازی کامل‌شده است؛ از اولین نتیجه، یک نقطه نمایش داده می‌شود و برای مشاهدهٔ روند حداقل دو نوبت کامل از یک بازی و نسخهٔ قواعد یکسان نیاز است. شاخص نمودار می‌تواند امتیاز کل یا یک مهارت باشد؛ مهارت بدون فرصت سنجش وارد نمودار نمی‌شود. تاریخچهٔ نتایج ناقص نیز قابل مشاهده است.

مقایسهٔ سن و مدرسه به تفکیک بازی و نسخهٔ قواعد است. علاوه بر میانگین نوبت‌ها، میانگین کودکان با وزن برابر و درصد هر مهارت همراه تعداد کودکان سنجیده‌شده در وب و Excel نمایش داده می‌شود. ابتدا میانگین نوبت‌های کامل هر کودک محاسبه می‌شود و سپس میانگین کودکان؛ تکرار بیشتر بازی وزن کودک را بیشتر نمی‌کند.

مدیر بر اساس شناسهٔ کودک، سن هنگام بازی، مدرسه هنگام بازی، بازی و تاریخ فیلتر می‌کند. جزئیات کودک شامل نوبت‌ها، مهارت‌ها، شمار تلاش‌ها، مراحل ساخت و رویدادهای خام است. میانگین گروه‌های سنی و مدارس تنها بر اساس نوبت‌های کامل است و تعداد کودک و نوبت کنار آن نمایش داده می‌شود. این اعداد ارتباط عملکرد با سن/مدرسه را توصیف می‌کنند و اثبات علت نیستند.

خروجی `.xlsx` با **همان فیلترهای فعال** هفت برگه دارد: راهنما، کودکان، بازی‌ها، مهارت‌ها، رویدادهای مراحل، گروه‌های سنی و مدارس. امتیاز خام، ظرفیت مسیر و شناسهٔ نوبت برای تحلیل مستقل در Excel قابل دسترسی‌اند. خروجی Word و گزارش تجمیعی قبلی نیز حفظ شده‌اند.

## اجرای محلی و کنترل کیفیت

Node.js 22، PostgreSQL 17 و تنظیمات `.env.example` مورد نیازند. اجرای API در ترمینال با متغیرهای محیطی انجام می‌شود؛ Docker Compose فایل `.env` را می‌خواند.

```bash
npm ci
npm run check
docker compose up -d --build
npm run dev
```

برای آزمون یکپارچه، **پایگاه دادهٔ جدا با نام پایان‌یافته به `_test`** تعیین کنید؛ این آزمون دادهٔ آزمایشی ایجاد می‌کند و نباید روی Production اجرا شود.

```bash
DATABASE_URL=postgres://test_user:test_password@localhost:5432/motefaker_test npm run test:platform
```

آزمون مرورگر `scripts/test-accounts-ui.py` به API آزمایشی در پورت ۳۳۰۱ و Vite در پورت ۵۱۷۳ نیاز دارد (`API_PROXY_TARGET=http://127.0.0.1:3301`). Chrome و Python Playwright لازم‌اند. CI بررسی‌های پروژه و آزمون یکپارچه روی PostgreSQL مجزا را اجرا می‌کند.

رمز سرور، رمز مدیریتی موجود و فایل `.env` نباید وارد Git شوند. استقرار فقط سرویس API و Nginx همین بازی را به‌روزرسانی می‌کند و volume موجود PostgreSQL حفظ می‌شود.

برای انتشار، تصویر API روی سیستم توسعه ساخته و آزمون می‌شود. `scripts/deploy-release.py` به Python و Paramiko نیاز دارد، رمز SSH را از `GAME_SSH_PASSWORD` دریافت می‌کند و فایل تصویر `tmp/kids-game-api-v2.tar.gz`، خروجی `dist` و شناسهٔ commit منتشرشده را مصرف می‌کند. این ابزار کلید میزبان شناخته‌شده، فضای آزاد، نسخهٔ پشتیبان دیتابیس و فایل محیط را کنترل می‌کند؛ سپس فقط کانتینرهای API و Nginx بازی را عوض می‌کند و تغییرنکردن سایر کانتینرها و فایل رمزهای SSH را بررسی می‌کند. فایل `tmp/deployment-result.json` محل پشتیبان و commit منتشرشده را ثبت می‌کند. پشتیبان فقط برای root قابل دسترسی است.

بازگشت نسخهٔ اجرایی از فایل `rollback.json` داخل پشتیبان انجام می‌شود: تصویر API قبلی و `dist` قبلی بازگردانده می‌شوند. مهاجرت نسخهٔ ۲ افزایشی است؛ هنگام بازگشت اجرایی، جدول‌های جدید و دادهٔ کاربران حذف نمی‌شوند. بازگردانی کامل دیتابیس باید تصمیم مستقلی بر اساس داده‌های ایجادشده پس از انتشار باشد.
# حساب آزمایشی مدیر

مدیرهای مستقل در جدول `admin_accounts` با رمز scrypt ذخیره می‌شوند. ورود پنل مدیر همچنان فقط با رمز انجام می‌شود؛ رمز مدیر اصلی در تنظیمات سرور نیز معتبر می‌ماند. غیرفعال کردن حساب مستقل با `enabled=false` ورود و نشست‌های آن حساب را لغو می‌کند. اطلاعات ورود حساب‌های آزمایشی در گیت ذخیره نمی‌شوند.

## ورود مستقل بازیکن

## ساخت مستقیم حساب توسط مدیر

در `/admin`، زبانهٔ «مدارس، دعوت و حساب‌ها»، بخش «ایجاد حساب والد یا بازیکن» قرار دارد:

- **والد:** نام کامل، نام کاربری و رمز؛ امکان ساخت هم‌زمان پروفایل کودک با نام، نام خانوادگی، سن ۳ تا ۱۸ و مدرسه.
- **بازیکن:** انتخاب والد فعال و کودک موجود بدون حساب بازیکن، یا ساخت پروفایل کودک جدید برای همان والد. ابتدا باید حساب والد وجود داشته باشد.
- نام کاربری ۴ تا ۴۰ نویسهٔ انگلیسی/عدد/نقطه/خط تیره/زیرخط و رمز حداقل ۱۰ نویسه است. شناسهٔ عمومی کودک خودکار ساخته می‌شود.
- اطلاعات ورود پس از ساخت برای تحویل نمایش داده می‌شود؛ رمز فقط به شکل هش ذخیره می‌شود. نشست مدیر حفظ می‌شود و نقش حساب جدید در سرور تعیین می‌شود.
- فهرست حساب‌ها نوع والد/بازیکن را نشان می‌دهد و امکان فعال/غیرفعال کردن و بازیابی دسترسی هر دو نقش را دارد. ساخت مستقیم فقط برای مدیر مجاز است؛ ثبت‌نام با کد دعوت همچنان در دسترس است.

آزمون رابط این بخش: `python scripts/test-admin-create-ui.py` با API آزمایشی ۳۳۰۱ و Vite ۵۱۷۳؛ این آزمون فقط روی دیتابیس آزمایشی اجرا شود.

والد در کارت کودک از «ساخت ورود مستقل بازیکن» نام کاربری و رمز تعیین می‌کند. بازیکن پس از ورود مستقیم به کتاب‌های همان کودک می‌رسد؛ مدیریت کودک، مدارس، پروفایل والد، گزارش والد و پنل مدیر برای او در سرور مسدود است. سابقهٔ امتیاز فقط برای نمایش نتیجه و ستاره‌های بازی خود او دریافت می‌شود. ثبت‌نام دعوتی همچنان حساب والد می‌سازد. نقش حساب از دیتابیس خوانده می‌شود؛ تغییر نقش روی نشست‌های قبلی هم اعمال می‌شود.
