# راهنمای تحویل و استقرار نسخه نهایی

تاریخ بسته: ۲۰۲۶/۱۰/۰۲ — نسخه برنامه: ۲٫۰٫۰

**این راهنما مرجع استقرار این بسته است.** راهنماهای قدیمی نسخه ۱ درباره انتشار صرفاً استاتیک، برای قابلیت‌های حساب و گزارش این نسخه کافی نیستند.

## ۱. محتویات و امکانات

- `src/` و `public/`: کد React/TypeScript و تصاویر و قلم‌ها.
- `server/`: API با Fastify، قواعد امتیازدهی و چهار فایل مهاجرت PostgreSQL.
- `dist/`: خروجی آماده رابط کاربری؛ برای انتشار نیازی به ساخت مجدد آن نیست.
- `Dockerfile.api` و `deploy/docker-compose.handoff.yml`: ساخت و اجرای کامل API، پایگاه داده و وب‌سرور.
- `docs/ACCOUNTS-AND-REPORTS.md`: راهنمای حساب‌ها، امتیازها و گزارش‌ها.
- `docs/CLIENT-REQUIREMENTS-AUDIT.md`: تطبیق خواسته‌های کارفرما با پیاده‌سازی.
- `RELEASE.json` و `SHA256SUMS.txt`: شناسه نسخه منبع و هش فایل‌های تحویل‌شده.

این نسخه شامل ورود خصوصی، نقش مستقل والد و بازیکن و مدیر، چند کودک برای هر والد، ثبت نام/نام خانوادگی/سن/مدرسه، ثبت رویدادها و پیشرفت در سرور، امتیاز/ستاره/مدال، گزارش والد و نمودار رشد، تحلیل مدیر بر اساس شناسه/سن/مدرسه، خروجی Excel و ایجاد مستقیم حساب والد یا بازیکن در پنل مدیر است. چهار بازی فعال هستند؛ شش کتاب دیگر برای توسعه آینده قفل‌اند.

**فایل `.env` واقعی، رمز SSH، داده‌های کاربران، نسخه پشتیبان دیتابیس و `node_modules` در بسته نیستند.** حساب‌ها و نتایج سرور فعلی با کپی کد منتقل نمی‌شوند. تصاویر اصلی برند در `assets-source/` برای توسعه نگهداری شده‌اند و لازم نیست روی وب عمومی منتشر شوند.

## ۲. پیش‌نیازها

برای مسیر زیر: سرور Linux با Bash و OpenSSL، Docker Engine و افزونه Docker Compose v2، دسترسی به اینترنت برای دریافت تصاویر و بسته‌های npm، فضای کافی برای تصویر API و دیتابیس. نصب عمومی این ابزارها را مسئول سرور متناسب با سیستم عامل انجام دهد. Node.js 22 و npm فقط برای توسعه یا بازسازی `dist` لازم‌اند؛ API داخل Docker اجرا می‌شود. PostgreSQL 17 داخل Compose اجرا می‌شود.

هاست صرفاً استاتیک یا هاست PHP بدون امکان اجرای Node.js/PostgreSQL برای کل این برنامه کافی نیست. رابط و `/api/` باید از یک دامنه و مبدأ ارائه شوند.

## ۳. نصب جدید و مستقل

این دستورها برای **نصب تازه با دیتابیس خالی** هستند؛ برای سرور فعلی به بخش ۸ مراجعه کنید. فایل ZIP را در پوشه مستقل مانند `/opt/motefaker-client` استخراج کنید و وارد پوشه `kids-web-game` شوید. اگر پورت ۸۳۹۷ اشغال است، مقدار `WEB_PORT` را تغییر دهید. نام پروژه `motefaker-client` را از اولین نصب ثابت نگه دارید؛ تغییر آن یک volume دیتابیس جدا ایجاد می‌کند.

```bash
cd /opt/motefaker-client/kids-web-game
bash deploy/init-handoff-env.sh
docker compose --env-file .env -p motefaker-client -f deploy/docker-compose.handoff.yml config --quiet
docker compose --env-file .env -p motefaker-client -f deploy/docker-compose.handoff.yml up -d --build
docker compose --env-file .env -p motefaker-client -f deploy/docker-compose.handoff.yml ps
curl -f http://127.0.0.1:8397/api/health
```

اسکریپت تنظیمات، رمز مدیر را دو بار از مسئول نصب می‌گیرد، هش آن و رمز تصادفی دیتابیس و Cookie Secret را در `.env` با دسترسی خصوصی ذخیره می‌کند. اگر `.env` موجود باشد آن را تغییر نمی‌دهد. مقادیر رمز و secret را بین به‌روزرسانی‌ها حفظ کنید. رمز دیتابیس تولیدشده hex است تا در URL اتصال نیاز به escape نداشته باشد؛ در صورت تنظیم دستی، کاراکترهای ویژه باید URL-encode شوند.

تنظیم اولیه وب فقط روی `127.0.0.1:8397` و HTTP است. برای مشاهده خصوصی از تونل SSH استفاده کنید:

```bash
ssh -L 8397:127.0.0.1:8397 YOUR_SSH_USER@YOUR_SERVER
```

سپس `http://localhost:8397/` و `http://localhost:8397/admin` را باز کنید. ورود مدیر فقط با رمز انتخاب‌شده است؛ نام کاربری لازم ندارد. در نصب تازه هیچ حساب آزمایشی، مدرسه یا کودک از قبل ساخته نمی‌شود. مهاجرت‌های SQL هنگام شروع API به‌صورت خودکار اجرا می‌شوند؛ اجرای دستی یا حذف جدول‌ها لازم نیست.

## ۴. دامنه و HTTPS

دامنه را به IP سرور متصل کنید و در وب‌سرور موجود فقط یک سایت مستقل برای این برنامه اضافه کنید. upstream آن `http://127.0.0.1:8397` باشد. نمونه زیر داخل بلوک `server` مربوط به **دامنه خود برنامه** قرار می‌گیرد؛ گواهی TLS و `listen 443 ssl` با ابزار یا تنظیمات موجود مسئول سرور تکمیل شود:

```nginx
server_name game.example.com;
location / {
    proxy_pass http://127.0.0.1:8397;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
}
```

روی HTTP پورت ۸۰ برای همین دامنه، درخواست‌ها را به HTTPS هدایت کنید. برای انتشار HTTPS مقدار `COOKIE_SECURE=true` را در `.env` بگذارید و سپس:

```bash
docker compose --env-file .env -p motefaker-client -f deploy/docker-compose.handoff.yml up -d api
sudo nginx -t
sudo systemctl reload nginx
```

`WEB_BIND=127.0.0.1` را برای این حالت حفظ کنید. TLS در reverse proxy میزبان خاتمه می‌یابد؛ تنظیم Nginx داخلی برای HTTP بین کانتینرها کافی است. این نمونه تنظیمات سایر سایت‌ها یا رمزهای SSH را تغییر نمی‌دهد. API و دیتابیس در Compose تحویل به اینترنت publish نشده‌اند.

## ۵. راه‌اندازی حساب‌ها و آزمون تحویل

1. با رمز انتخابی به `/admin` وارد شوید.
2. در «کاربران و عملکرد ← مدارس، دعوت و حساب‌ها» ابتدا مدرسه بسازید.
3. از بخش «ایجاد حساب والد یا بازیکن»، حساب والد با نام کامل، نام کاربری و رمز بسازید؛ می‌توانید هم‌زمان کودک را با نام، نام خانوادگی، سن ۳ تا ۱۸ و مدرسه ثبت کنید.
4. حساب بازیکن را به والد فعال و کودک موجود بدون ورود مستقل وصل کنید، یا کودک جدید برای همان والد بسازید. شناسه `K-…` خودکار تولید می‌شود. رمز حداقل ۱۰ نویسه و نام کاربری ۴ تا ۴۰ نویسه انگلیسی/عدد/نقطه/خط تیره/زیرخط باشد.
5. اطلاعات نمایش‌داده‌شده پس از ساخت را به صاحب حساب تحویل دهید. ثبت‌نام با کد دعوت نیز همچنان قابل استفاده است.
6. در مرورگر یا نشست جدا، والد و بازیکن را امتحان کنید. والد فقط خانواده خودش را ببیند؛ بازیکن فقط بازی‌های کودک خودش را داشته باشد و به مدیریت کودک یا گزارش والد و مدیر دسترسی نداشته باشد.
7. یک بازی را کامل کنید؛ سپس گزارش والد، مراحل/رویدادها در مدیر و خروجی Excel با فیلتر سن/مدرسه/شناسه را بررسی کنید.
8. برای روند رشد حداقل دو نوبت کامل از یک بازی و نسخه امتیازدهی یکسان نیاز است؛ اولین نتیجه یک نقطه نمودار ایجاد می‌کند. نمودار توصیف عملکرد بازی است، نه تشخیص بالینی رشد.
9. صفحه را refresh و دوباره وارد شوید تا ذخیره پیشرفت و نتیجه بررسی شود.

نشانی نسخه موجود: `http://141.11.1.223:8397/` و پنل مدیر: `http://141.11.1.223:8397/admin`. حساب‌های آزمایشی موجود مربوط به دیتابیس همان سرورند و در نصب تازه خودکار ایجاد نمی‌شوند. اطلاعات ورود آزمایشی قبلاً جداگانه تحویل شده است.

## ۶. توسعه و بازسازی

در ریشه پروژه با Node.js 22:

```bash
npm ci
npm run check
```

دستور `check` آزمون قراردادها، lint، بررسی TypeScript سرور و ساخت رابط را انجام می‌دهد. برای توسعه می‌توانید از Compose اصلی ریشه (`docker-compose.yml`) جهت API روی `localhost:3001` و دیتابیس استفاده کنید و `npm run dev` را اجرا کنید؛ آن روش با Compose کامل تحویل دو مسیر جایگزین‌اند. تنظیمات `.env` را پیش از اجرای هر کدام آماده کنید. Vite درخواست `/api/` را به پورت ۳۰۰۱ proxy می‌کند. در صورت استفاده از Compose تحویل که API داخلی است، برای Vite مقدار `API_PROXY_TARGET=http://127.0.0.1:8397` تعیین کنید.

آزمون یکپارچه `npm run test:platform` فقط با `DATABASE_URL` دیتابیس جدا و نام پایان‌یافته به `_test` اجرا شود؛ این آزمون داده ایجاد می‌کند. جزئیات آزمون‌های مرورگر در `docs/ACCOUNTS-AND-REPORTS.md` است. دستورهای آزمون را روی دیتابیس واقعی کاربران اجرا نکنید.

## ۷. پشتیبان‌گیری و به‌روزرسانی نصب تحویل

دستورهای این بخش در Bash، از ریشه همین نصب و با همان نام پروژه اجرا شوند:

```bash
backup_dir="backups/$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$backup_dir"
chmod 700 "$backup_dir"
docker compose --env-file .env -p motefaker-client -f deploy/docker-compose.handoff.yml exec -T postgres pg_dump -U motefaker -d motefaker -Fc > "$backup_dir/database.dump"
test -s "$backup_dir/database.dump"
cp -p .env "$backup_dir/environment"
cp -a dist "$backup_dir/dist"
docker compose --env-file .env -p motefaker-client -f deploy/docker-compose.handoff.yml images > "$backup_dir/images.txt"
docker compose --env-file .env -p motefaker-client -f deploy/docker-compose.handoff.yml images -q api > "$backup_dir/api-image-id.txt"
docker image save "$(cat "$backup_dir/api-image-id.txt")" | gzip > "$backup_dir/api-image.tar.gz"
gzip -t "$backup_dir/api-image.tar.gz"
```

بسته قدیمی منبع را نیز نگه دارید و پشتیبان را به محل خصوصی خارج از همین سرور کپی کنید. سپس فایل‌های منبع، تنظیمات نسخه و `dist` جدید را جایگزین کنید؛ `.env` و volume را حفظ کنید. به‌روزرسانی فقط برنامه:

```bash
docker compose --env-file .env -p motefaker-client -f deploy/docker-compose.handoff.yml up -d --build --force-recreate api web
curl -f http://127.0.0.1:8397/api/health
```

`--force-recreate` باعث می‌شود mount پوشه `dist` بعد از تعویض پوشه دوباره resolve شود. دستور `docker compose down -v`، حذف volume، بازسازی رمز دیتابیس یا اجرای `docker system prune` بخشی از این روند نیست و داده/سرویس‌های موجود را به خطر می‌اندازد.

برای بازگشت اجرایی، ابتدا خروجی `dist` قبلی و فایل‌های نسخه قبلی را برگردانید. تصویر ذخیره‌شده را با `docker load -i PATH/api-image.tar.gz` بارگذاری و آن را برای سرویس API در یک Compose override با `image: IMAGE_ID_OR_TAG` و `pull_policy: never` تعیین کنید؛ سپس با همان نام پروژه و `up -d --no-build --force-recreate api web` و هر دو فایل Compose اجرا کنید. نام فایل override را در عملیات بعدی حفظ یا آگاهانه حذف کنید. بازگردانی دیتابیس اقدام جداگانه‌ای است و داده‌های ایجادشده پس از پشتیبان را از بین می‌برد؛ برای رفع خطای رابط، دیتابیس را برنگردانید.

## ۸. تفاوت نصب جدید با سرور فعلی

سرور فعلی برنامه در `/opt/kids-web-game` و دیتابیس آن در volume موجود است؛ کانتینر وب `kids-web-game-demo` پورت ۸۳۹۷ را مصرف می‌کند. **Compose تحویل را روی همان پورت و به‌عنوان جایگزین خودکار نصب فعلی اجرا نکنید:** نام پروژه و volume متفاوت، دیتابیس خالی جدا ایجاد می‌کنند.

برای به‌روزرسانی نصب فعلی باید فایل `.env`، نام پروژه/volume موجود، فایل‌های override فعلی، تصویر API و تنظیمات Nginx را حفظ و پیش از تغییر پشتیبان بگیرید. روند اختصاصی فعلی در `deploy/README.md` و `scripts/deploy-release.py` مستند است؛ اسکریپت به checkout گیت با commit مشخص، Python/Paramiko، تصویر API از قبل ساخته‌شده، `dist` و متغیر موقت `GAME_SSH_PASSWORD` نیاز دارد و کلید میزبان فعلی را کنترل می‌کند. بسته ZIP فاقد `.git` است و مستقیماً پیش‌نیاز این اسکریپت را فراهم نمی‌کند.

برای انتقال کاربران و نتایج به سرور تازه، علاوه بر این بسته باید یک `pg_dump` خصوصی از دیتابیس فعلی و تنظیمات محیطی لازم به‌صورت جدا و امن منتقل و روی دیتابیس مقصد تازه با `pg_restore` بازیابی شوند. این بسته شامل داده واقعی نیست. مسئول استقرار باید قبل از import مالکیت و سطح دسترسی داده‌های کودکان را هماهنگ کند.

## ۹. عیب‌یابی

```bash
docker compose --env-file .env -p motefaker-client -f deploy/docker-compose.handoff.yml logs --tail=100 api web postgres
docker compose --env-file .env -p motefaker-client -f deploy/docker-compose.handoff.yml exec web nginx -t
```

- خطای 502: وضعیت API و اتصال Nginx به `api:3001` را بررسی کنید.
- ورود موفق نیست یا نشست نمی‌ماند: روی HTTP مقدار Cookie Secure باید false و روی HTTPS true باشد؛ frontend و API باید روی یک مبدأ باشند.
- API بالا نمی‌آید: هش مدیر ۶۴ رقم hex، Cookie Secret حداقل ۳۲ نویسه و اتصال دیتابیس را بررسی کنید.
- حساب‌های قبلی دیده نمی‌شوند: نام پروژه/volume و دیتابیس مقصد را کنترل کنید؛ ZIP حاوی حساب‌ها نیست.
- روند رشد خالی است: نوبت کامل‌شده و یکسان بودن بازی/نسخه قواعد را بررسی کنید.
- اطلاعات گزارش دیر می‌رسد: اتصال و ارسال صف رویدادهای معوق همان کودک را بررسی کنید.

قبل از ارسال log برای دیگران، رمز، secret و داده هویتی کودکان را حذف کنید.
